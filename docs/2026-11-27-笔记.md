# 第4章：任务规划与分解 核心笔记

> 来源：Datawhale《Deep Agents 实战》第4章
> 说明：原始链接无法直接访问，以下内容基于该项目 GitHub 开源内容整理。

## 1. 为什么需要规划能力？

对于简单任务（如查天气），Agent 可以一步到位。但面对复杂任务（如"调研架构、对比竞品、写报告"），缺乏规划的 Agent 容易出现**遗漏关键步骤、重复劳动、半途而废**等问题。规划能力让 Agent 先拆解任务，再逐步执行并动态调整。

## 2. 核心变化：v0.7 起需显式启用

**这是本章最重要的版本信息**。在 Deep Agents v0.7 之前，`write_todos` 是默认配置；但从 v0.7 开始，它不再自动注入。你需要手动传入 `TodoListMiddleware` 才能让 Agent 获得规划能力。

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import TodoListMiddleware

agent = create_deep_agent(
    model=model,
    middleware=[TodoListMiddleware()],  # 显式启用
)
```

**启用建议**：
- 单步问答或短任务建议关闭（避免"计划比任务长"）
- 长程、多阶段任务建议开启
- 若 UI 需要展示进度，`todos` 也可作为产品状态数据源

## 3. `write_todos` 工具与任务状态

启用后，Agent 通过 `write_todos` 创建和管理清单。每个任务包含 `content`（内容）和 `status`（状态）两个字段，状态流转为：

**`pending`（待办）→ `in_progress`（进行中）→ `completed`（已完成）**

> **注意**：`completed` 仅是 Agent 写入的进度标记，**不代表任务质量合格**。应用层仍需核查实际产物（如报告是否生成、代码是否通过测试）。

## 4. 任务清单的持久化与子 Agent 隔离（重要更正）

任务清单持久化在 **Agent State** 中，这意味着即使对话历史被总结压缩，清单依然完整。

关于子 Agent，需要注意一处**官方勘误**：默认的 `general-purpose` 子 Agent **不会**继承主 Agent 的 `TodoListMiddleware`。子 Agent 需要规划能力时，必须在自己的配置中显式启用 `TodoListMiddleware`，且其清单与主 Agent 相互隔离。

## 5. 与上下文管理的协同

在长任务中（如执行到第 6 步），对话历史会变得很长。此时上下文管理机制（如大结果卸载、对话总结）会介入，压缩发给模型的消息。

**关键点在于：总结压缩不会删除单独保存的 `todos` 字段**。这份清单能帮助 Agent 在"失忆"后依然知道：
- 总共有哪些步骤
- 哪些已完成
- 下一步该做什么

## 6. 底层机制：LangChain 中间件

`write_todos` 本质上是 LangChain **中间件（Middleware）** 系统的一个插件。`create_deep_agent()` 的工作就是把一组中间件自动组装到 Agent 上。

如果你想自定义规划提示词或扩展功能，了解中间件的 **Node-style Hook**（如 `before_model`）和 **Wrap-style Hook**（如 `wrap_model_call`）的区别会很有帮助。
