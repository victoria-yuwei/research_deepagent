# 一次 Agent 调用把 32K 上下文撑爆了：从 cp .env.example .env 到 GLM-4-9B 报错的完整复盘

**关键词**：AgentSeek、DeepAgents、Tavily、GLM-4-9B、上下文超限、.env 配置、LangSmith

---

## 一、起因：一条天气查询把模型干趴了

我给 research_deepagent 发了一句：

> 帮我查查明天北京通州的天气

Agent 调用 `tavily_search`，返回 3 条结果，然后直接报错：

```text
OpenAIInvalidRequestError: Error code: 400
{'code': 20015, 'message': 'number of input tokens (34349) has exceeded max_seq_len (32768) limit.'}
```
输入 34349 token，模型上限 32768 token，爆了。

---

## 二、为什么上下文这么长

Tavily 返回的不是“明天通州晴，0~6℃”这一句话，而是三个天气网站的**整页原始文本**：

| 结果 | 来源 | 估算 token |
| :--- | :--- | :--- |
| 1 | 天气网 m.tianqi.com | ~1.5 万 |
| 2 | 中国天气网 weather.com.cn | ~1 万 |
| 3 | 全国天气网 tianqi.so.com | ~8 千 |
| **合计** | **+ 指令 + 工具调用记录** | **34349** |

真正的答案只有几十个字，其余 95% 以上是：导航栏、侧边栏、页脚、版权信息、几十个其他城市链接、历史天气、生活指数、景点推荐、广告位、无关新闻标题。

**结论：不是问题变长了，是搜索工具把整页网页倒进了上下文，把 32K 窗口撑爆了。**

---

## 三、根因拆解

1. **Tavily 默认返回条数偏多**：3 条整页结果，每条都是完整网页文本。
2. **模型上下文偏小**：THUDM/GLM-4-9B-0414 上限 32768 token，属于小窗口模型。
3. **没有做结果裁剪**：Agent 把原始搜索结果直接塞进下一轮模型输入，没有摘要、没有过滤。
4. **搜索词不够精准**：`明天北京通州天气` 命中的是综合天气页，而不是结构化单日预报页，噪音更大。

---

## 四、解决方案（按见效速度排序）

### 方案 1：调小 `max_results`（最快）
把 Tavily 搜索返回条数从 3 调到 1。一条结果足以回答天气问题，直接砍掉约 2/3 的 token。

### 方案 2：提示词要求“先摘要再回答”
在 Agent 指令里加一句：
> 搜索后只提取与问题直接相关的信息，忽略导航、广告、其他城市内容；如结果过长，先摘要再作答。

### 方案 3：换更大上下文的模型
如果任务本身就需要读长网页，把 `AGENTSEEK_MODEL` 换成 128K 上下文的模型，而不是 32K 的 GLM-4-9B。

### 方案 4：用更精准的搜索词
`通州 明天 天气 11月18日` 比 `明天北京通州天气` 更容易命中结构化天气页，减少无关内容。

---

## 五、顺带厘清的配置问题（新手常见坑）

### 1. `cp .env.example .env` 是什么
把模板复制成本地实际配置：
* `.env.example`：提交到 Git，只含变量名和占位值，无秘密。
* `.env`：被 `.gitignore` 忽略，填真实密钥，不进版本控制。

### 2. `frontend/.env` 和后端 `.env` 的分工
| 文件 | 作用 | 放什么 |
| :--- | :--- | :--- |
| 根目录 `.env` | 后端 Agent 进程读取 | `OPENAI_API_KEY`、`TAVILY_API_KEY`、`LANGSMITH_API_KEY`、模型配置 |
| `frontend/.env` | 浏览器前端读取 | 只放后端 URL 和 Vite 端口，**绝不放密钥** |

密钥写进前端 = 打包进浏览器 = 公开泄露。

### 3. `AGENTSEEK_MODEL=deepseek-ai/DeepSeek-V3.2` 为什么是两级
这是 Hugging Face 模型 ID 规范：`组织名/模型名`。斜杠前是发布组织（如 `deepseek-ai`、`THUDM`），斜杠后是模型名，用来在共享平台上保证唯一性。

### 4. `AGENTSEEK_PARALLEL_TOOL_CALLS=false` 是什么
关闭 Agent 的并行工具调用。设为 `false` 后，模型每轮只能调一个工具，串行执行。适用于：工具间有依赖/副作用、需要固定顺序调试、模型不擅长并行调用。

### 5. `Authorization: Bearer sk-xxx` 的 `Bearer` 能省吗
**不能。** `Bearer` 是 OAuth 2.0 的认证方案标识符（RFC 6750），告诉服务器“后面是持有者令牌”。硅基流动等 OpenAI 兼容网关都要求这个固定前缀，且 `Bearer` 与密钥之间必须有一个空格。

### 6. LangSmith 是干嘛的
LangChain 官方的可观测性平台。开启后（`LANGSMITH_TRACING=true` + `LANGSMITH_API_KEY`），Agent 每次运行的模型调用、工具调用、token 用量、延迟都会被记录成 trace，用于调试和排查。控制台在 `smith.langchain.com`。不调试可保持关闭，不影响 Agent 运行。

### 7. `agentseek doctor` 和 `--live` 的区别
* `agentseek doctor`：检查配置和环境（文件、变量是否齐）。
* `agentseek doctor --live`：额外探测服务是否真的活着（2024 后端健康检查、5174 前端可达）。
* 全绿 = 配置齐了 + 服务跑起来了。

### 8. Claude 和 Gemini 不是一家
| 产品 | 公司 |
| :--- | :--- |
| Claude | Anthropic（独立公司） |
| Gemini | Google（DeepMind） |

三者原生协议不同，但都提供 OpenAI 兼容层，所以可以用一套 `openai` provider 写法对接不同厂商。

---

## 六、安全提醒

对话中曾出现未打码的真实 `OPENAI_API_KEY`（`sk-bthyxj...`）。密钥一旦贴到聊天、截图或提交进 Git 就等同于泄露，应立即去平台后台吊销并重新生成，新 key 只写进本地 `.env`（并确认 `.env` 在 `.gitignore` 里）。

---

## 七、一句话总结

**Agent 上下文超限，十有八九不是模型不行，而是你把整页网页喂给了它。** 先砍搜索结果条数，再要求摘要，最后才考虑换大窗口模型。

> 本文基于 AgentSeek research_deepagent 模板 + 硅基流动 GLM-4-9B + Tavily 搜索的真实调试过程整理。
